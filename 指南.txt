# 导航语音播报引擎完整规格（高德等价版 · 合并稿）

## 0. 使用说明与设计前提

本文是给 **AI 编程助手** 直接使用的实现规格。目标不是解释“高德大概怎么播”，而是把高德类语音导航的**可计算规则**拆成状态、队列、距离判定、车道编码和模板系统，让 AI 能在 ETS2 插件数据之上实现一个**行为等价**的播报引擎。

你的插件已经能识别车道、弯道、距离。在进入播报逻辑之前，必须先把这些**几何/地图数据**抽象成导航引擎的标准输入单元：**Maneuver（机动事件）**。

每个 Maneuver 至少包含：

| 字段 | 含义 |
|---|---|
| `id` | 全局唯一标识（建议用节点索引 + 类型） |
| `type` | `TURN_LEFT / TURN_RIGHT / KEEP_LEFT / KEEP_RIGHT / ROUNDABOUT_EXIT / HIGHWAY_EXIT / HIGHWAY_ENTER / UTURN / RAMP / MERGE` |
| `road_class` | `HIGHWAY / TRUNK / PRIMARY / SECONDARY / LOCAL` |
| `distance_to_maneuver` | 沿路径的剩余距离（米），**必须由插件实时更新** |
| `exit_number` | 环岛/多出口场景的出口序号（从进入路口起逆时针计数，进入口为 0） |
| `road_name_after` | 机动后的道路名称（可为空；ETS2 中通常为空） |
| `lane_hint` | 可选，目标车道提示，使用第 7 节的结构化编码 |
| `next_maneuver` | 紧随其后的下一个 Maneuver，用于两步联合播报 |

所有播报决策只读这些字段，**不直接读原始弯道几何**。这是让 AI 能够写出清晰状态机的前提。

## 1. 播报时机：不是“到距离就播”，而是“语音在参考点恰好结束”

高德类导航的核心时间逻辑是：**当车辆到达一个“语义参考点”时，关于该机动的那句话应该正好说完，而不是刚开始播**。

### 1.1 触发距离公式

设：

- `D_ref` = 参考距离，即你想在机动点多远处“说完”的那句话中提到的距离；
- `T_speech` = 该句语音的实际时长（现实秒），由 TTS 返回或预配置；
- `V` = 当前车速，单位为“游戏内米 / 现实秒”；
- `T_prep` = 系统准备时间，通常 0.1 s 量级。

则**播报触发距离**：

```
D_trigger = D_ref + V × (T_speech + T_prep)
```

含义：在 `D_trigger` 处触发播报，语音持续 `T_speech` 秒，期间车辆前进 `V × T_speech` 米，语音结束时车辆恰好位于 `D_ref` 参考点。

**关键推论**：同一个 Maneuver 在不同速度下，**触发距离不同**。静止时 `V=0`，触发距离就是 `D_ref`；高速行驶时触发距离会显著提前。这解释了为什么导航在市区和高速上的播报“提前量”感觉完全不同。

### 1.2 何时用哪一级 `D_ref`

普通地图可直接参考下表。ETS2 因比例尺分区，推荐用第 6 节的“目标提前秒数”反算 `D_ref`，下表作为现实语义参考。

| 道路等级 | 远距参考 | 中距参考 | 近距参考 | 执行参考 |
|---|---|---|---|---|
| 高速公路 / 快速路 | 2000 m | 1000 m | 500 m | 0 m（“现在驶出/现在右转”） |
| 主干道 / 国道 / 省道 | 500 m | 300 m | 100 m | 0 m |
| 次干道 / 城市道路 | 300 m | 100 m | 50 m | 0 m |
| 低等级道路 / 小路 | 100 m | 50 m | 30 m | 0 m |

**远距/中距播报是可选的，近距和执行播报是强制核心。**

## 2. 播报层级与模板系统

### 2.1 三层播报结构

高德的“啰嗦感”来自**同一机动在多个距离点用不同详细度重复**，但每次重复的信息量不同：

**L1 · 预告层（Early / Advance）**  
在远距参考点触发。只给“方向 + 大致距离”，不给车道细节。  
> “前方 2 公里，靠右行驶，进入匝道。”

**L2 · 准备层（Prepare / Approach）**  
在中距或近距参考点触发。给出操作、道路名称，以及必要的车道/出口信息。  
> “前方 500 米，请靠右，从第 2 出口驶出环岛。”

**L3 · 执行层（Execute / Now）**  
在 `D_ref = 0` 或极小距离时触发。极短、只给动作。  
> “现在右转。” / “现在驶出。”

**AI 实现规则**：

- 每个 Maneuver 维护一个 `spoken_levels: Set<Level>`，L1/L2/L3 各最多触发一次。
- L1 不是必需的，但在 `distance_to_maneuver` 初始大于远距参考值时必须触发。
- L3 必须在 `distance_to_maneuver ≤ 0` 且车辆尚未通过机动点时触发；通过后不再触发 L3，转入“已通过/偏航”逻辑。

### 2.2 通用模板

**L1/L2 通用模板**：

```
“前方” + 剩余距离 + 驾驶操作 + “去往” + 道路名称 + 可选附加并道提示
```

ETS2 无道路名时，用第 5 节的方向词和车道指令替代“去往 + 道路名称”。

**L3 / 路口处模板**：

```
“前方” + 路口类型 + “请进入” + 转向类型 + “前往” + 道路名称
```

路口类型枚举：分岔口、出入口、环岛、十字路口、丁字路口、Y 形岔路口。

### 2.3 特殊场景的专用规则

**环岛**：必须播报出口序号，而不是“左转/右转”。规则：进入环岛的路口计为第 0 出口，沿行驶方向（欧卡为逆时针方向，与国内一致）依次计数。常规 4 出口环岛中，第 1 出口≈右转，第 2 出口≈直行，第 3 出口≈左转，第 4 出口≈掉头；但**播报文本始终用“第 X 出口”**，不要用方向词替代。L2 模板：

> “前方进入环岛，请从第 3 出口驶出。”

**靠左 / 靠右 ≠ 转弯**：当 `type` 为 `KEEP_LEFT` / `KEEP_RIGHT` 时，播报文本必须是“靠左行驶 / 靠右行驶”，**禁止**生成“左转/右转”。这在高速分岔、匝道分流中极其常见。

**多出口匝道 / 分岔**：如果有连续出口且目标不是第一个，L2 必须加入“**不要驶出**”的抑制提示：

> “前方 500 米靠右，请勿从当前出口驶出，继续沿主路行驶。”

**两步联合播报（Two-part）**：当 `next_maneuver` 存在且两个机动之间的距离小于“当前速度 × 8 秒”或固定阈值如 **150–300 m**，L2 合并为一句：

> “前方 500 米右转，然后立即左转。”  
> “靠右进入匝道，然后靠左侧行驶，走左侧两车道。”

**车道提示的触发条件**：只有在 `lane_hint` 存在且**当前所在车道与目标车道不顺应**时才附加。顺应时不播报，避免啰嗦。插件既然能识别车道，就应计算“当前车道 → 目标车道”是否需要并线。

## 3. 播报优先级、队列与打断

### 3.1 优先级层级

从高到低：

| 优先级 | 类型 | 行为 |
|---|---|---|
| **P0 · 紧急** | 偏航重算、立即掉头、严重超速 | **可打断任何正在播报的内容**，清空普通队列 |
| **P1 · 执行/安全** | L3 “现在右转/驶出”、碰撞预警 | 可打断 P2/P3，但不应被 P2 打断 |
| **P2 · 准备** | L2 播报、环岛出口、高速出口 | 队列中等待，不打断正在播报的 P1/P2 |
| **P3 · 预告** | L1 远距预告、路线开始、到达 | 最低，可被 P0/P1/P2 打断或丢弃 |

### 3.2 队列与打断规则

**普通入队**：P2/P3 进入 **FIFO 队列**。如果当前没有播报，立即出队播报；如果有，等待当前播报完成。

**打断条件**：仅当 `new.priority` 高于 `current.priority` 且满足以下之一：

- `new.priority == P0`：无条件打断，清空队列中所有 P2/P3。
- `new.priority == P1` 且 `current.priority >= P2`：打断当前 P2/P3，保留队列中尚未播报的 P1，清空 P2/P3。

**打断后的恢复**：被 P0 打断的当前播报**不恢复**，偏航后旧指令已失效。被 P1 打断的 P2 播报**不恢复**，通常车辆已接近机动点，旧 L2 已无意义。不要实现“打断后续播”的复杂恢复，高德的实际行为更接近**丢弃低优先级，让新的高优先级自然接管**。

### 3.3 最小间隔与冷却

全局维护 `last_speech_end_time`。在冷却窗口内，**P2/P3 不触发**，P0/P1 不受限。

建议值：

- `MIN_INTERVAL = 8–10 秒`：相邻两条普通播报之间的最小间隔。
- 同一 Maneuver 的**相同层级**绝不重复；同一 Maneuver 的不同层级之间间隔不得小于 **5 秒**，防止 L1 刚结束 L2 立刻触发，除非距离已经穿越了 L2 的触发点。

## 4. 状态机与去重：防止“原地反复播”

### 4.1 每个 Maneuver 的局部状态

```
UNAWARE → ANNOUNCED_L1 → ANNOUNCED_L2 → ANNOUNCED_L3 → PASSED
```

- `UNAWARE`：尚未触发任何播报。
- `ANNOUNCED_Lx`：已播报对应层级。**转移不可逆**，但允许在 `ANNOUNCED_L1` 状态下直接跳到 `ANNOUNCED_L2`，如果车辆速度快，跳过了 L1 的触发窗口。
- `PASSED`：`distance_to_maneuver` 变为负值且持续超过一定距离/时间。进入 `PASSED` 后该 Maneuver 不再产生任何播报。

### 4.2 全局去重索引

这是“静止在转弯口语音反复播 3–4 次”问题的标准解法：

```
_last_spoken_maneuver_id:  ManeuverId | null
_last_spoken_level:        Level | null
_last_spoken_at:           timestamp
```

触发播报前检查：

```
if (maneuver.id == _last_spoken_maneuver_id
    && level <= _last_spoken_level
    && distance_to_maneuver 未发生“从 > 触发点 到 ≤ 触发点”的穿越
) then 抑制
```

更简单的等价规则：**同一 `(maneuver_id, level)` 对在本次行程中全局只允许播报一次**。车辆静止导致距离不再变化，但 `(id, level)` 已经播过，自然不会再触发。

### 4.3 偏航触发的状态重置

当检测到车辆偏离规划路径时：

1. 将**所有** Maneuver 的局部状态重置为 `UNAWARE`，清空播报队列中的 P2/P3。
2. 立即触发 **P0 播报**：“已重新规划路线”或“请在前方掉头”，视重算结果。
3. 重算完成后，新路径上的 Maneuver 从 `UNAWARE` 开始，但偏航前已经 `PASSED` 的机动点如果在新路径上不再出现，不要恢复。

## 5. ETS2 无道路名时的方向词与模板

### 5.1 比例尺问题：播报距离必须做尺度适配，不能直接用“现实距离 × 19”

欧卡2 的地图尺度是**分区段不同**的：欧洲大陆主路约 **1:19**，英国约 **1:15**，城市区域会降到 **1:3** 左右。

这意味着：游戏内显示的“500 米”，在现实语义中大约相当于 9.5 公里主路距离。如果直接把游戏内 `distance_to_maneuver` 填进模板，说“前方 500 米右转”，玩家看到的距离和听到的距离一致，但**语音提前量相对于游戏车速会严重不足**。因为 TTS 一句话约 3 秒，游戏内 3 秒按 90 km/h 只走约 75 米，但在 1:19 尺度下这 75 米游戏距离对应的现实语义约 1.4 公里。玩家在高速上会感觉“刚说完就要转了”。

**正确做法是引入“播报尺度适配层”**：

```
播报距离 = 游戏内距离
```

不要乘 19。`scale_factor` 不应设成 19。直接按**游戏内速度 × 目标提前秒数**来选取播报参考距离：

```
D_ref = V_游戏内米每秒 × T_advance
```

其中：

- `V_游戏内米每秒` 是游戏内速度换算为“游戏内米 / 现实秒”；
- `T_advance` 是目标提前秒数；
- 主路目标提前秒数：**40–70 s**；
- 城市区域目标提前秒数：**15–25 s**。

例如要复现“2 公里预告、约 72 秒提前”的感知：`90/3.6 × 72 ≈ 1800 游戏米`。也就是说，在欧卡主路 1:19 尺度下，“2 公里级预告”在游戏内对应距离大约 1.8–2.0 公里，而不是把现实 2 公里乘 19。如果乘 19，会变成 38 游戏公里，语音会在刚上高速时就说“前方 38 公里驶出”，完全失去意义。

**单位系统必须统一**：

- `distance_to_maneuver`、`D_ref`、`D_trigger` 全部用**游戏内米**；
- `V` 用**游戏内米 / 现实秒**；
- `T_speech`、`T_prep` 用**现实秒**；
- 公式 `D_trigger = D_ref + V × (T_speech + T_prep)` 中乘积得到游戏内米，单位一致。

语音时长 `T_speech` 用现实秒，`V` 用游戏内速度，`D_ref` 和 `D_trigger` 全部用游戏内米。分区段只影响目标提前秒数，不影响比例尺本身的乘法。

### 5.2 无道路名：用“方向 + 车道 + 拓扑关系”作为替代坐标系

欧卡2 原生数据没有高德那样可读的道路名称字段。高德播报中“进入 [道路名]”的信息，在 ETS2 场景里必须由**方向词、车道指令、出口编号、下一动作**共同替代。

JT/T 1354-2020 对“无道路名时如何用方向词表达”给出了可操作规范，核心是按**转向角度区间**映射用语：

| 转向角度 | 播报用语 |
|---|---|
| -20°～20° | 请直行 |
| -20°～-60° | 请向右前方行驶 |
| -60°～-120° | 请右转 |
| -120°～-180° | 请向右后方行驶 |
| 20°～60° | 请向左前方行驶 |
| 60°～120° | 请左转 |
| 120°～180° | 请向左后方行驶 |
| 高速公路出口，**不进入匝道** | 请靠左行驶 |
| 高速公路出口，**进入匝道** | 请靠右行驶 |
| 分岔处走最左/最右/中间车道 | 请走最左侧/最右侧/中间车道 |

“靠左行驶 / 靠右行驶”的标准定义是**选择左侧或右侧的“道路分支”**，而不是在单条路内部变道。在欧卡中，这正好对应高速出口处分流、匝道分流、主路/辅路分岔等场景。插件识别出“当前路径相对于前车道的左右偏移方向”后，直接映射到上表用语，就完成了对“道路名”的语义替代。

无路名播报的**基本模板**：

```
“前方” + 距离 + [方向词 / 车道指令] + “然后” + 下一动作
```

不再出现“进入 XX 路”，而是把“进入哪条路”的信息承载在**出口编号、第几车道、左/右侧分支**上。

## 6. 车道数量播报与结构化编码

车道数量播报是高德车道级导航的关键，也是新手最容易误解的地方。

| 播报用语 | 语义 | 可走车道（以 4 车道为例） |
|---|---|---|
| **“走左侧三车道”** | 左边 3 条**都可以走** | 第 1、2、3 车道 |
| **“走左侧第三车道”** | **只走**从左数第 3 条 | 仅第 3 车道 |
| **“走右侧两车道”** | 右边 2 条**都可以走** | 第 3、4 车道（从右数第 1、2 条） |
| **“最右侧车道”** | **只走**最右边 1 条 | 第 4 车道 |
| **“右侧第二车道”** | **只走**从右数第 2 条 | 第 3 车道 |
| **“右侧第三车道”** | **只走**从右数第 3 条 | 第 2 车道 |
| **“中间两车道”** | 靠近中心的两条**都可以走** | 第 2、3 车道 |

**编码规则（给 AI 用）**：

- `数量词 + “车道”`，如“两车道”“三车道”，表示**集合**，范围内任意车道可走。
- `序数词 + “车道”`，如“第二车道”“第三车道”，表示**单条**，必须在该车道。
- **“最右侧/最左侧”** 等价于“右侧第一/左侧第一”，单条。
- 侧向基准：**“左侧第 N”从最左往右数；“右侧第 N”从最右往左数**。不要混用其他基准。

`lane_hint` 结构化字段：

```
lane_hint: {
  mode: "SET" | "SINGLE",
  side: "LEFT" | "RIGHT" | "CENTER",
  index: 2,        // SINGLE 时生效；从对应侧数第 index 条
  count: 2         // SET 时生效
}
```

播报引擎按上表选择模板。组合弯道示例：

> “前方 500 米靠右进入匝道，**然后**靠左侧行驶，走左侧两车道。”

间距更近时压缩为：

> “靠右进入匝道，**然后立即**靠左，走左侧两车道。”

## 7. 高德等价播报语句库

以下语句以**中文、无道路名版**为主，括号内给出触发条件或模板变量。有道路名时，把“进入/去往 [道路名]”加回即可。

### A. 启动与行程

| 场景 | 语句 |
|---|---|
| 导航开始 | “路线已规划，全程约 XX 公里。” |
| 开始导航后首句 | “出发后请沿当前道路行驶。” |
| 进入高速主路 | “已进入高速，请保持车速，注意车道。” |

### B. 直行与沿路

| 场景 | 语句 |
|---|---|
| 长距离沿路 | “沿当前道路继续行驶 XX 公里。” |
| 长距离后预告 | “继续行驶 XX 公里后，[动作]。” |
| 直行通过路口 | “前方路口请直行。” |
| 直行并准备后续动作 | “前方路口请直行，稍后[动作]。” |

### C. 转弯与方向（JT/T 1354 角度映射）

| 场景 | 语句 |
|---|---|
| 左转 | “前方 XX 米左转。” / “请左转。” |
| 右转 | “前方 XX 米右转。” / “请右转。” |
| 左前方 | “前方请向左前方行驶。” |
| 右前方 | “前方请向右前方行驶。” |
| 左后方 | “前方请向左后方行驶。” |
| 右后方 | “前方请向右后方行驶。” |
| 掉头 | “前方路口请掉头。” / “请在合适位置掉头。” |

### D. 靠左 / 靠右（道路分支，非转弯）

| 场景 | 语句 |
|---|---|
| 高速出口不驶出，保持主路 | “请靠左行驶。” |
| 高速出口驶入匝道 | “请靠右行驶。” |
| 前方岔路走左侧分支 | “靠左行驶。” |
| 前方岔路走右侧分支 | “靠右行驶。” |
| 带距离 | “前方 XX 米靠左/靠右行驶。” |
| 靠右进入匝道后需继续 | “靠右进入匝道，然后[下一动作]。” |

| 单条，最左 | “请走最左侧车道。” |
| 单条，最右 | “请走最右侧车道。” |

### F. 组合弯道 / 两步播报

| 场景 | 语句 |
|---|---|
| 动作 A 后紧跟动作 B | “[A]，**然后** [B]。” |
| 间距较近，强调立即 | “[A]，**然后立即** [B]。” |
| 例：右匝道后靠左双车道 | “靠右进入匝道，然后靠左侧行驶，走左侧两车道。” |
| 例：右转后左转 | “右转，然后左转。” |
| 执行完 A 后预告 B | “已[完成 A]，前方 XX 米[B]。” |
| 两个动作之间需变道 | “[A]，然后走右侧第 N 车道，[B]。” |

### G. 环岛

| 场景 | 语句 |
|---|---|
| 进入环岛，出口 ≥2 | “前方进入环岛，请从第 X 出口驶出。” |
| 带距离 | “前方 XX 米进入环岛，请从第 X 出口驶出。” |
| 经过中间出口时提醒 | “经过第 X 出口，继续沿环岛行驶。” |
| 即将驶出 | “现在驶出环岛。” |
| 出口 1 | 可用“前方环岛，请右转驶出”，但 **X≥2 必须用出口编号**。 |

环岛出口编号规则：**进入环岛的路口计为第 0 出口，沿行驶方向（欧卡逆时针）依次编号**；4 出口环岛中第 4 出口≈掉头。

## 8. 特殊场景的完整播报序列

### 8.1 高速驶出（HIGHWAY_EXIT）

```
L1（D_ref = 2000 m 或 1000 m，ETS2 用目标提前秒数反算）：
  “前方 2 公里，靠右驶出。”

L2（D_ref = 500 m，ETS2 用目标提前秒数反算）：
  “前方 500 米，请靠右，准备驶出。”
  [如果 next_maneuver 很近，追加 “然后……”]

L3（D_ref = 0）：
  “现在驶出。”
```

### 8.2 环岛（ROUNDABOUT_EXIT）

```
L1（D_ref = 500 m / 300 m）：
  “前方进入环岛，请从第 X 出口驶出。”

L2（D_ref = 100 m / 50 m）：
  “前方环岛，第 X 出口驶出。”

L3（D_ref = 0）：
  “现在驶出环岛。”
```

如果 `exit_number == 1`，L1 可以简化为“前方环岛，请右转驶出”；但 `exit_number ≥ 2` 时**必须用出口序号**。

### 8.3 靠左 / 靠右分岔（KEEP_LEFT / KEEP_RIGHT）

```
L2（D_ref = 500 m / 300 m）：
  “前方靠右行驶。”
  [如果 lane_hint 存在且不顺应：“请走右侧两车道。”]

L3（D_ref = 0）：
  “靠右行驶。”
```

**绝不生成“右转”**。

### 8.4 立即掉头（UTURN）

UTURN 的优先级为 P1，通常由偏航或路线需要触发。`D_ref` 使用近距参考。播报文本：“前方请掉头。” 如果距离极近（< 30 m），直接用 L3：“现在掉头。”

### 8.5 路线开始 / 到达

- **路线开始**：在导航开始时播报一次，属于 P3，但可延迟到车辆开始移动后 1–2 秒再播，避免与引擎声/环境声重叠。内容：“路线已规划，全程 X 公里，预计 Y 分钟，出发后请沿当前道路行驶。”
- **到达**：`distance_to_destination ≤ 50 m` 时触发 P1：“前方即将到达目的地。”到达后触发一次 P3：“已到达目的地附近。”

## 9. 语音时长、速度补偿与 TTS 配置

`D_trigger = D_ref + V × (T_speech + T_prep)` 已经内建了速度补偿。**不要**再额外加一个“高速多提前”的拍脑袋系数。唯一需要按道路等级调整的是 `D_ref` 的选取。

`T_speech` 不要硬编码。如果 TTS 引擎在合成后返回时长，用返回值；如果没有，用 `文本字符数 / 语速系数` 估算，但**不同语言/语音包的系数不同**。为每个语音包维护一个 `chars_per_second` 配置，初始值可设为中文 **4.5–5 字/秒**、英文 **2.8–3.2 词/秒**，再根据实际语速调参。

ETS2 的坐标/时间尺度必须统一：如果插件输出的 `distance_to_maneuver` 是游戏内米，`V` 也必须是**游戏内米 / 现实秒**，`T_speech` 是现实秒。不能混用现实米和游戏秒，否则触发距离会系统性偏移。建议在引擎入口处统一换算到“游戏内米 + 游戏内米/现实秒 + 现实秒”这一套单位系统。

## 10. AI 实现检查清单

交给 AI 编程助手时，让它逐项确认：

1. Maneuver 抽象是否包含 `id / type / road_class / distance / exit_number / road_name_after / lane_hint / next_maneuver`？
2. 每个 Maneuver 是否有 `spoken_levels` 状态集，且 `(id, level)` 全局只播一次？
3. 触发距离是否使用 `D_trigger = D_ref + V × (T_speech + T_prep)`，而不是固定距离？
4. 优先级队列是否实现 P0 可无条件打断并清空 P2/P3，P1 可打断 P2/P3，P2/P3 普通 FIFO？
5. 是否实现了全局最小间隔，P2/P3 之间至少 8–10 秒？
6. 环岛是否用“第 X 出口”而非“左转/右转”？
7. `KEEP_LEFT/RIGHT` 是否严格生成“靠左/靠右”，绝不生成“转弯”？
8. 偏航时是否清空队列、重置状态、优先播报 P0 重算提示？
9. `T_speech` 是否来自 TTS 返回值或按语音包配置的语速系数，而非硬编码？
10. 游戏内距离/速度是否与语音时长的单位系统一致，没有混用现实米和游戏秒？
11. ETS2 比例尺是否通过“游戏内速度 × 目标提前秒数”选取 `D_ref`，而不是把现实距离乘以 19？
12. 无道路名时是否使用 JT/T 1354 方向词表，把“进入某路”替换为方向、车道、出口编号和拓扑关系？
13. 车道播报是否严格区分 `mode=SET`（“右侧两车道”）与 `mode=SINGLE`（“右侧第二车道”）？
14. 组合弯道是否只在两个机动点间距小于“速度 × 8 秒”或固定 150–300 m 阈值时使用“然后”，否则分句播报？
15. 无路名播报是否保证“距离 + 方向 + 车道”构成完整语义，不生成“前方 500 米，然后靠左”这种缺少第一动作的句子？
